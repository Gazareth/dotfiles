# Atlantis: Assignment Navigation & Target-Hint Mechanism

**Commit:** `2e56b66` — `fix(nvim): Atlantis - Fix 'jump to' actions for assignment lhs & rhs`

This set of changes wires up meaningful "jump to name" and "jump to value" actions for assignment statements in Atlantis. Previously, both actions either did nothing useful or reopened Atlantis on the wrong node. The fix required a chain of interconnected changes: giving assignments proper `NavigationTarget` fields with ranges, making `variable_list` a recognised container so the LHS has a meaningful landing point, and introducing a target-hint mechanism in the surveyor so that Lua can pin the ancestry search to a specific node by type and position — preventing ambiguity when multiple recognised nodes share the same start column.

| File | Change | Purpose |

| [lua.rs](myPlugins/atlantis-surveyor/src/model/lang/languages/lua.rs) | `variable_declaration` value: was using grandchildren; now text-parses the `=` offset to compute the RHS column | Works around the one-level-deep children limitation to produce a real `NavigationTarget` for "jump to value" |
